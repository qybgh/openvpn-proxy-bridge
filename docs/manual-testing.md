# OpenVPN Proxy Bridge 手工验收清单

本文用于发布前手工验收。建议复制一份清单记录结果，不要在文档、截图或聊天中填写 VPN 密码。

## 1. 测试范围与优先级

- **P0**：本机发布前必须通过的主流程。
- **P1**：异常输入、恢复、重启和并发场景，建议通过。
- **P2**：需要另一台 Mac、干净环境或可能影响现有 Homebrew 软件的兼容性场景。

发生 `AUTH_FAILED` 时不要连续重试。错误凭据场景最多执行一次，随后使用 `update-credentials.command` 恢复正确凭据。

## 3. 通用验收标准

### A. 已连接

- `status-company-vpn.command` 显示“已连接”。
- 只有一个 `run-openvpn.sh` 监控器和一个使用 `runtime.ovpn` 的 OpenVPN 进程。
- 公司目标路由的 `interface` 是 `utun`。
- 公司内网测试端口可达。
- 普通公网和出海代理仍可正常使用。
- 没有持续弹出管理员授权窗口或重复启动终端窗口。

参考命令：

```bash
route -n get COMPANY_IP
nc -G 5 -zv COMPANY_IP COMPANY_PORT
ps axww -o pid=,ppid=,user=,command= | grep -E 'Proxy-OpenVPN|runtime\.ovpn' | grep -v grep
```

### B. 已停止

- `status-company-vpn.command` 显示“未连接”。
- 不存在本工具的监控器或 OpenVPN 子进程。
- 公司目标路由不再走 `utun`。
- `runtime.ovpn`、`connected.state`、`attempt.started`、`transport.state` 和 `current-proxy.state` 不存在。
- 出海客户端保持连接，普通公网代理正常。

### C. 已卸载

- `/Library/Application Support/Proxy-OpenVPN` 不存在。
- `/Library/LaunchDaemons/com.local.proxy-openvpn.plist` 不存在。
- 不存在本工具的监控器或 OpenVPN 子进程。
- 公司目标路由不再走本工具创建的 `utun`。
- 用户原始 `.ovpn` 文件和 OpenVPN Connect 图形客户端仍存在。
- Homebrew OpenVPN 是否保留，必须符合安装时选择的托管策略。

必要时使用以下只读检查：

```bash
sudo test ! -e '/Library/Application Support/Proxy-OpenVPN' && echo '配置目录已删除'
sudo test ! -e '/Library/LaunchDaemons/com.local.proxy-openvpn.plist' && echo 'LaunchDaemon 已删除'
pgrep -fal 'Proxy-OpenVPN|runtime\.ovpn'
brew list --versions openvpn
```

## 4. 建议执行顺序

1. 记录当前 Homebrew 和 VPN 基线。
2. 执行卸载及重复卸载。
3. 执行未安装状态下的入口脚本测试。
4. 完成一次全新安装。
5. 完成状态、重复操作、停止和立即重启测试。
6. 完成凭据、代理变化和网络异常恢复测试。
7. 完成重启 Mac 测试。
8. 完成已连接状态卸载和卸载残留检查。
9. 重新安装，确保最终交付状态符合需要。

## 12. 代理自动发现与手动配置

- [ ] **PRX-01 / P0：自动发现系统 SOCKS5**
  - 操作：选择 `auto`，启动出海客户端并运行启动脚本。
  - 预期：状态显示当前本机 SOCKS5 地址和端口，VPN 连接成功。

- [ ] **PRX-02 / P0：手动配置有效代理**
  - 操作：选择 `manual`，填写实际回环地址和 SOCKS5 端口，再重启公司 VPN。
  - 预期：使用手动地址连接成功。

- [ ] **PRX-03 / P0：手动恢复自动模式**
  - 操作：重新选择 `auto` 后停止并启动。
  - 预期：`proxy.conf` 被删除，重新使用系统代理。

- [ ] **PRX-04 / P1：非法模式**
  - 操作：输入非 `auto`/`manual` 值。
  - 预期：明确报错，不修改现有代理配置。

- [ ] **PRX-05 / P1：非回环地址**
  - 操作：手动输入局域网或公网地址。
  - 预期：拒绝保存，仅允许 `127.0.0.1`、`localhost` 或 `::1`。

- [ ] **PRX-06 / P1：非法端口**
  - 操作：分别测试空值、字母、`0`、`65536`。
  - 预期：均拒绝保存，不覆盖原有效配置。

- [ ] **PRX-07 / P1：合法但未监听的端口**
  - 操作：保存一个当前未监听的合法端口后启动。
  - 预期：不能建立 OpenVPN，失败后无残留；恢复正确端口后可连接。

- [ ] **PRX-08 / P0：出海客户端端口动态变化**
  - 操作：保持公司 VPN 在线，让出海客户端切换本地 SOCKS5 端口。
  - 预期：旧 OpenVPN 被停止，后台使用新端口重建；必要时再次完成二次认证。

- [ ] **PRX-09 / P1：代理短暂消失后恢复**
  - 操作：保持监控器运行，临时关闭出海代理，再重新开启。
  - 预期：不会直连公司 VPN；旧隧道停止；代理恢复后使用当前端口重新连接。

- [ ] **PRX-10 / P1：停止时代理已经关闭**
  - 操作：先关闭出海客户端，再运行停止脚本。
  - 预期：本工具进程、路由和状态仍能清理；不会因为无法重新探测代理而卡住。

- [ ] **PRX-11 / P1：不提供控制接口的 SOCKS5 客户端**
  - 操作：使用支持 UDP 的普通本机 SOCKS5，但没有 Clash 兼容控制接口。

## 13. 路由、DNS 与分流

- [ ] **NET-01 / P0：公司主机路由**
  - 操作：连接后检查公司测试 IP。
  - 预期：路由走 `utun`，公司端口可达。

- [ ] **NET-02 / P0：公司网段路由**
  - 操作：抽查 profile 或服务端下发的多个公司网段。
  - 预期：均走同一个公司 VPN `utun`。

- [ ] **NET-03 / P0：普通公网路由**
  - 操作：检查普通公网 IP 的系统路由并访问常用网站。
  - 预期：没有被公司 VPN 默认路由接管；出海代理正常。

- [ ] **NET-04 / P0：停止后的路由回收**
  - 操作：停止公司 VPN 后再次检查公司测试 IP。
  - 预期：不再走公司 `utun`，没有陈旧公司路由。

- [ ] **NET-05 / P1：公司 DNS**
  - 操作：分别测试公司 IP 和公司域名。
  - 预期：IP 与域名均可用；若 IP 可通而域名失败，记录为 DNS 问题。

- [ ] **NET-06 / P1：外层连接经代理**
  - 操作：在出海客户端连接列表中查找 OpenVPN 服务器 UDP 会话。
  - 预期：目标由出海代理处理，不是本机直接连接。

- [ ] **NET-06A / P0：VPN 服务器没有直连规则**
  - 操作：检查出海客户端的自定义路由，确认 VPN 服务器 IP 未设置为直连或拦截；默认规则已走代理时不添加额外规则。
  - 预期：OpenVPN 外层 UDP 会话经过当前出海节点；公司内网分流由 OpenVPN `utun` 路由负责。

- [ ] **NET-06B / P0：公司业务域名使用直连规则**
  - 操作：将公司内网业务域名或域名后缀设置为直连，分别测试浏览器 HTTPS 和非代理 SSH。确认 VPN 外层连接的元数据使用目标 IP、没有被业务域名规则命中。
  - 预期：浏览器请求由出海客户端交回本机，并按目标 IP 的 OpenVPN 路由进入 `utun`；HTTPS 和 SSH 均可访问。

- [ ] **NET-06C / P1：错误规则对照**
  - 操作：仅在受控测试中临时关闭公司业务域名直连规则，确认请求链路后立即恢复。
  - 预期：浏览器请求可能进入出海节点而失败，SSH 仍可因不使用系统代理而正常；恢复直连规则后网页恢复。

- [ ] **NET-07 / P1：增强模式或 TUN 模式**
  - 操作：在已经通过系统代理模式验收后开启出海客户端增强模式。
  - 预期：此模式当前不在通用支持范围。记录公司路由、公司 DNS 和普通公网结果；发生异常后退出出海客户端并以普通系统代理模式重启，确认本工具自动恢复。

- [ ] **NET-08 / P2：含 `redirect-gateway` 的公司 profile**
  - 操作：仅用测试 profile 验证。
  - 预期：若普通公网被公司 VPN 接管，则判定不符合本工具的分流前提，不作为支持场景。

## 18. 发布判定

### 必须全部通过

- 所有 P0 用例。
- `INS-12`、`RUN-06`、`RUN-07`、`UNI-01`、`UNI-03`、`UNI-10`。
- 最终没有多余进程、公司残留路由、未关闭授权窗口或测试临时文件。

### 允许带说明发布

- P1 中与特定代理客户端控制接口、增强模式或网络切换相关的兼容性差异。
- P2 中需要另一台机器或独立 Homebrew 依赖环境的场景，但必须记录“未测试”和原因。

```text
用例 ID：
执行时间：
执行前状态：已连接 / 已停止 / 已卸载 / 连接中
实际操作：
预期结果：
实际结果：
终端错误：
status-company-vpn.command 输出：
是否出现二次认证：是 / 否 / 不适用
是否可稳定复现：是 / 否
恢复方式：
```

不要在失败记录中粘贴 VPN 密码、完整 `auth.txt` 或包含私密证书的 profile 内容。
